# Backup restoration

Settings contains sound/account cards, one compact backup workspace and then reset/delete controls. The backup workspace has no page min-height. Full account export/import is available when signed in; browser language export/import works for the current guest or account. Importing another browser file into an account is explicit, never automatic on login.

Export and file-selection actions share outlined rounded buttons with matching icon spacing and a minimum 44-pixel touch target. Desktop actions align at the bottom of their columns; compact layouts allow labels to wrap without overflow.

Account format CWDOJOW2 retains the eight-byte magic plus SHA-256 body checksum and six-byte frame header (type, input, little-endian u32 payload length). Type 0 is a profile checkpoint, type 2 a language packet, and type 3 a rich block: applied u8, created f64 LE, ID length u16 LE and UTF-8 ID, packet length u32 LE and packet, then derived record bytes. Account files contain no identity credentials. Legacy CWDOJOW1 type-1 block packets lack IDs and server-applied flags: restore saved profiles, retain these blocks as explicitly labeled extra/imported history, and do not treat them as qualifying chart evidence. The preview explains this limitation.

Import accepts at most 32 MiB, 10,000 frames and 8 MiB per packet/checkpoint. Reject wrong magic/checksum, truncation, unknown frame types, invalid profiles, duplicate/conflicting IDs, invalid records and unsupported versions before writes. Binary files are persisted; JSON is only transient interface/preview metadata. Browser CWLANG01 retains its existing length-framed layout.

The server validates account files through isolated Rust/WASM workers. Preview returns counts, compatibility warnings and the current epoch/profile revisions. Confirm uploads the same bytes with a SHA-256 digest and typed RESTORE, checks the preview baseline before and after validation, then replaces only the authenticated owner's records/profile snapshots in one transaction and rotates its epoch. Imported derived records are validated/re-derived; accepted historical policy annotations are preserved. Packet scores and persisted input categories must agree. Return a conflict without mutation if another device changes state. Revisions/epoch invalidate old pending uploads. On success the browser clears stale local outboxes/language cache and reloads the current profile. Cancelling preview does nothing. Sign-in and recent-session policies remain intact.

Browser-only import decodes every packet first, previews new/duplicate counts and destination, rejects conflicting same-ID packets, and merges valid packets in a single IndexedDB transaction. Signed-in imports require a current server epoch/cursor and use one authenticated atomic batch endpoint, avoiding per-record request limits; an offline guest import stays local. Existing pending records with conflicting remote bytes remain exportable rather than being overwritten. Unsupported packets remain exportable in existing storage but are rejected for new import with an actionable error, never silently dropped.

Verification covers round trips (both input profiles, accepted/extra blocks, language records), legacy compatibility, checksum/truncation, duplicate/conflicting IDs, unknown versions, cancellation, owner isolation, revision/reset races and compact/wide themes. Back up production SQLite before backend deployment. Never import into real production learner data during smoke testing.
